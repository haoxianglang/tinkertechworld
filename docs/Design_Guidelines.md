# TTW 网站设计与修改一致性指南

版本：1.1 · 设计基线：2026-09-16 已实现的网站版本（多伦多时间）

目录更新：网站已完整复制到同一 TTW 项目下的 `05_website/`。后续默认在该目录修改；原 Dropbox 网站仓库保留为来源副本，当前没有自动同步。

本文供后续 AI 和人工维护者在修改网站前阅读。目标是在现有 TTW 网站上持续改进，让新页面、新内容和旧页面保持同一品牌、视觉与交互体系。本文记录当前设计基线，不代表课程、收费或营业安排已经获得确认。用户之后明确提出的新要求优先于本文；调整设计方向时同步更新此指南。

## 1. 网站定位与设计目标

TTW 是以动手实践、机器人与工程学习为核心的教育品牌。网站主要帮助家长回答：孩子适合从哪里开始、会做什么、如何成长、下一步怎样联系或申请体验。

设计关键词：**专业、温暖、清晰、有探索感、对孩子友好但不幼稚**。

- 以真实学习过程建立信任：构思、搭建、编程、测试、改进、表达。
- 同时提供“按课程”和“按年龄”两个入口，避免要求家长先懂技术才能选课。
- 主行动始终是 **Contact Us / 联系我们**（2026-09-17 由 "Book a Trial Class / 预约体验课" 改名，页面从 `/book-a-trial.html` 迁移到 `/contact-us.html`，申请表单与校验逻辑未变）；辅助行动是浏览课程、联系 TTW 和加入课程。页脚同时存在 "Contact TTW"（`/contact.html`）与 "Contact Us"（`/contact-us.html`）两个相邻但不同的入口，如显得重复/易混淆，请与用户确认是否需要调整措辞或合并。
- 保留原有 TTW Logo 和品牌识别，不因新增页面更换一整套模板或视觉语言。
- 内部报告的“工程蓝图”文档风格只适用于内部资料；不要直接套用于家长网站。

## 2. 视觉系统

### 色彩

优先使用 `assets/site.css` 中已有的 CSS 变量。不要在单个页面随意引入新的品牌主色。

| 变量 / 用途 | 当前色值 | 使用指导 |
|---|---|---|
| `--paper` / 页面背景 | `#FBFAF6` | 暖白底，保持轻松、明亮 |
| `--white` / 卡片背景 | `#FFFFFF` | 课程、年龄、表单等内容容器 |
| `--ink` / 主文字与深色区块 | `#152F3B` | 标题、正文、深色横幅 |
| `--muted` / 次要文字 | `#50646C` | 描述、辅助信息，不再任意降低透明度 |
| `--line` / 分隔线 | `#D9E1DF` | 轻边框、列表分隔，避免粗重描边 |
| `--orange` / 主要行动 | `#FAAC45` | 体验课等主要按钮；搭配深色文字 |
| `--blue` / 蓝色强调 | `#087CAA` | 强调、焦点等；不将整页铺成高饱和蓝色 |
| `--green` / 学习与探索强调 | `#187A5A` | 小标题、步骤标记、勾选符号 |
| `.tinted` / 浅色分区 | `#EDF2EF` | 大区块交替背景 |
| 深色区块内的小标题 | `#AFD6CA` | 用浅色保证对比度，不能直接沿用深绿色 |

现有课程插画底色包括浅蓝、浅绿、浅橙、浅紫。它们用于分类和层次，正文仍使用统一深色。状态信息必须有文字，不能只靠颜色表达。

### 字体与文字层级

使用系统字体，不依赖外部字体服务：

```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Arial,
             "PingFang SC", "Microsoft YaHei", sans-serif;
```

| 层级 | 当前基线 | 修改原则 |
|---|---|---|
| 正文 | `16px / 1.65` | 保持舒适阅读，不缩小正文来塞内容 |
| H1 | `clamp(2.6rem, 5.5vw, 4.8rem)` | 每页一个，说明该页的核心意义 |
| H2 | `clamp(2rem, 3.6vw, 3.15rem)` | 划分主要章节 |
| H3 | `1.35rem` | 卡片及子区块标题 |
| 导语 `.lead` | `1.15rem / 1.7` | 简短解释，避免横跨整个大屏 |
| 小标题 `.eyebrow` | `.74rem`，较粗 | 英文可用大写与字距；不能承载唯一的重要信息 |

首页和内页在手机上有各自字号覆盖，扩展时优先复用这些规则。中英文分别检查断行；不要为了复制英文的行数强迫中文换行，也不要用固定高度裁掉译文。

### 布局、间距与形状

- 内容最大宽度 `1180px`；桌面两侧最少 `24px`，手机最少 `18px`。
- 普通大区块上下留白：桌面 `80px`，手机 `52px`。
- 卡片间距通常 `22px`；卡片内边距桌面 `27px`、手机 `24px`。
- 通用卡片圆角 `18px`；按钮 `7px`；行动横幅 `22px`。
- 以留白、浅底色和细边框建立层次。阴影用于少量浮层，不给每个元素添加厚重阴影。
- 首页主图保留较有识别度的不对称圆角和轻微错位背景；普通课程卡片保持简洁。
- 新增尺寸优先参考相邻组件；确实需要通用新样式时在共享 CSS 中命名，不逐页堆叠内联样式。

## 3. 组件使用约定

| 组件 / 实现入口 | 使用约定 |
|---|---|
| `render()`、`.site-header`、`.footer` | 全站共用页眉页脚、语言入口及元数据；不要复制一份独立导航到新页面 |
| `button()`、`.button.primary` | 橙底深字，用于主要下一步；同一区块不要有多个互相争抢的主按钮 |
| `.button.outline`、`.text-link` | 次要行动和延伸阅读；链接说明目标，不只写“点击这里” |
| `program_cards()`、`.program-card` | 固定顺序：示意图、适合年级、名称、开放状态、简介、详情链接 |
| `age_cards()`、`.age-card` | 四个年龄段保持顺序与视觉对应：3–6 年级、7–9 年级、高中、成人 |
| `.status` | 用短文字区分核心方向、规划中、登记意向或已核实的实际状态；不要为了转化删除状态 |
| `heading()`、`program_page()` | 复用内页标题及课程详情结构，不为每门课程创造完全不同的布局 |
| `.process`、`.process-item` | 用于真实的连续步骤，文字解释应比装饰编号更突出 |
| `.notebook` | 深色学习示例或工程思考区块，保持短小、可读 |
| `cta()`、`.banner` | 页面后段统一体验课入口，说明下一步，而不是制造紧迫感 |
| `faqs()`、`details/summary` | 使用原生可展开问答，支持键盘，不改成仅悬停可见的内容 |
| `booking()`、`.form-card`、`.review` | 复用申请、校验、核对和发送交接流程，不能只替换按钮文字却改变行为含义 |

完整课程列表最后一张卡片是”帮助选课”，用于引导不确定的家长，**不是新增的课程**；它会跟随 `content/site.json` 中实际课程数量自动出现在末尾。在只显示相关课程的内页（如按年龄筛选），无需为凑满网格增加虚构产品。

## 4. 页面结构与导航

首页保持以下叙事顺序，局部修改应继续服务这条家长决策路径：

1. 品牌价值、首屏主图、预约体验与浏览课程。
2. 按年龄寻找起点。
3. 全部课程卡片与明确的开放状态。
4. TTW 的学习方式：构思与搭建 → 测试与改进 → 解释与连接。
5. 如何观察进步与理解项目过程。
6. 家长常见问题。
7. 体验申请横幅与完整页脚。

课程详情通常包括：定位与适合人群 → 开放状态和咨询入口 → 学习内容 → 项目示例 → 入门要求与报名前需了解的信息 → 后续方向 → 行动入口。

桌面主导航优先放课程、年龄、FLL、WRO、营地、关于和体验申请；WRO 虽已并入课程体系（`/programs/wro.html`），但用户明确要求保留其主导航入口，不要移除。项目展示、FAQ、联系等通过页脚及正文链接到达。不要把所有子页面塞进页眉。完整路由以 [Information_Architecture.md](Information_Architecture.md) 为准；保留已有可用 URL，变更路由时同时处理旧入口。

## 5. 手机与交互规则

当前主要响应式断点为 `1090px` 和 `760px`，`360px` 以下另有紧凑调整；这些是现有实现基线，不应在不同页面重复创造冲突断点。

- 课程网格从三列变两列，再变一列；年龄卡片从四列变两列，极窄屏变一列。
- 手机首屏上下排列文字和主图，不能把桌面双栏简单等比例缩小。
- 手机页眉保留 Logo、品牌名和菜单；隐藏品牌长标语及冗余顶部联系文字。语言入口不得拆字换行。
- 菜单按钮维护 `aria-expanded`，支持键盘展开和 Escape 关闭；关闭后焦点可回到按钮。
- 手机底部保留体验申请入口，但申请及加入课程页面本身不再重复显示；页面底部预留空间，避免遮住页脚和最后一个控件。
- 无 JavaScript 时导航和正文仍可访问，申请页有直接邮件回退入口。
- 主按钮和主要触控控件至少约 `44px` 高；表单输入目前至少 `48px`。
- 保留可见键盘焦点、跳到正文链接及 `prefers-reduced-motion` 支持。
- 不增加自动播放视频、自动轮播、强制弹窗、闪烁装饰或只有悬停才能使用的操作。

## 6. 图片、图标与真实性

- 原始 Logo：网站仓库 `image/logo.png`；当前优化版：`assets/logo.webp`。保持比例，不拉伸、不随意重绘或换色。
- 当前主图来源是已有 `image/Makerspace.png`，使用本地 WebP 响应式版本。它是概念示意图，必须保留可见说明，不能当作真实营业场地照片。
- 课程图标由 `icon()` 中的 SVG 提供，沿用一致的深色线条、少量品牌色和简单几何形状。扩充图标时匹配现有视觉，而不是混用 emoji、彩色贴纸和另一套图标包。
- 项目示例不能写成学生实际成果；真实作品、人物、场地照片需有可用依据和相应发布许可。
- 图片有适当 alt、宽高及优化尺寸；装饰图形隐藏于辅助技术。不要把重要文字做进图片。
- 保留主图优先加载和非关键图片按需加载。避免因换图重新引入数 MB 的首屏资源。

## 7. 文案、双语与转化

文案对家长说清楚“会做什么、为什么值得学、适合谁、如何开始”。语气温暖直接，技术名词要连接到具体学习活动。避免空泛的“改变未来”、无依据的领先地位、获奖数字或升学承诺。

| 场景 | 推荐表达 | 避免表达 |
|---|---|---|
| 学习成果 | “搭建、测试，并解释机器人为何能运行” | “保证培养未来工程师” |
| 未来课程 | “规划中，可登记意向” | 无排期却写“立即报名，仅剩两席” |
| 体验申请 | “核对申请 → 打开邮件发送 → 等待 TTW 确认” | 未投递就显示“预约成功” |
| 项目展示 | “项目示例，活动以确认课程为准” | 将概念插画标成学生实拍 |

每个英文页面都有对应 `/zh/` 页面。课程、导航、按钮、状态、FAQ、表单提示及隐私说明都要同步修改。中文可以自然表达，不必逐字翻译，但业务含义和承诺必须一致。

当前体验流程没有自动投递后端或实时席位系统。修改样式时保留“尚未发送”和“需确认”的边界；增加真实预约服务后，按实际成功、失败和待确认状态重写流程。课程价格、税费、地址、FLL/WRO 开班状态等以已核实信息为准，不能从报告建议直接变成营业事实。证据与冲突处理见 [Content_Map.md](Content_Map.md) 和 [Website_Spec.md](Website_Spec.md)。

## 8. AI 实施工作方式

当前网站源码与后续修改的默认工作目录位于：

```text
/Users/haoxiang/Library/Mobile Documents/iCloud~md~obsidian/Documents/TTW/05_website
```

| 修改类型 | 优先修改位置（相对网站仓库） |
|---|---|
| 课程、年龄和通用业务数据 | `content/site.json` |
| 页面组合、双语编辑内容、共用组件 | `scripts/build_site.py` |
| 色彩、字号、间距、响应式布局 | `assets/site.css` |
| 菜单、表单及交互状态 | `assets/site.js` |
| 图像资源 | `assets/`，同时保留必要原始文件 |
| HTML、站点地图和 robots | 由构建脚本生成，不作为逐页手改入口 |

修改流程：

1. 先读本目录 [README.md](README.md)，再读本指南和任务相关规范；检查实际代码及现有未提交修改。
2. 找到最接近的已有页面或组件，优先复用。普通内容/样式调整不需要重新搭建网站、迁移框架或更换品牌。
3. 在源数据或共用模板中修改，保持中英文及同类组件一致。
4. 在网站目录运行 `python3 scripts/build_site.py`，再运行 `python3 tests/check_site.py`。
5. 根据改动范围检查浏览器效果和交互。涉及共享布局时查看首页、课程页、申请页及中英两种长度；检查 320、390、768、1024、1440px，不只看桌面首页。
6. 影响表单、导航、可访问性时运行对应浏览器或无障碍检查，方法见 [Technical_Architecture.md](Technical_Architecture.md)。文档文字修改无需重跑整站测试。
7. 如用户要求了新的全局设计方向，更新本指南及受影响规范，说明新旧规则；局部改动不能悄悄变成新设计系统。

文档与代码有差异时，代码用于核实当前实际行为，本文用于理解设计意图；先核对用户的新要求及修改记录，再修正文档或实现，不把任意一方的漂移自动认作最新批准。此目录是跨 AI 的规范入口；网站仓库 `docs/` 中同名副本如有维护，也应同步，避免出现相互矛盾的版本。

## 9. 修改完成前的简短检查清单

- [ ] 页面仍然像同一个 TTW 网站：Logo、颜色、字体、卡片、按钮和页眉页脚一致。
- [ ] 信息有清晰主次，家长能看懂适合谁、学什么、下一步怎么做。
- [ ] 主行动仍可找到；规划中与实际开放状态没有混淆。
- [ ] 中英页面及相关课程/年龄入口同步，链接和元数据有效。
- [ ] 手机无横向溢出，译文不裁切，语言入口不断字，固定元素不遮挡操作。
- [ ] 键盘焦点、表单标签、错误提示和真实交互状态保留。
- [ ] 概念图和示例有标识；没有新增未经证实的经营承诺。
- [ ] 修改发生在可维护的源文件，共用组件没有分叉，必要验证已完成。
