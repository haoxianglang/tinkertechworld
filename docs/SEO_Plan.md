# SEO Plan

## Intent and page ownership
| Search intent | Landing page | Content focus |
|---|---|---|
| Robotics / STEM learning in Markham | Home | Brand proposition, grades, pathways, trial request |
| LEGO robotics classes | LEGO Robotics | Mechanisms, block coding, sensors, entry readiness |
| Coding for kids / teens | Coding | Physical outcomes; core block coding vs planned Python |
| Electronics / CAD / maker learning | Respective subject | Unique learning goals and clearly future availability |
| Grade-specific STEM | Respective age page | Starting level and related subjects |
| FIRST LEGO League information | FLL | Readiness discussion, official source, no team claim |
| STEM camps | Camps | Future camp interests, not false dated listings |
| TTW contact / trial | Contact / Book a Trial | Working inquiry handoff |

Do not equate multiple keyword landing pages with multiple currently operating products. No doorway city pages or fabricated location footprints. Use Markham as service context, not a confirmed street-address listing.

## Implemented
- Unique titles, meta descriptions and one H1 per page.
- Canonical absolute HTTPS URL, reciprocal en-CA / zh-Hans / x-default alternate links.
- JSON-LD EducationalOrganization on Home using known brand/contact/city data only; WebPage on inner pages.
- Open Graph and Twitter large-image metadata; existing image described as a concept illustration.
- Generated XML sitemap for canonical public pages in both languages; excludes 404 and legacy store.
- robots.txt with sitemap discovery, no tracking parameters in canonical URLs.
- Semantic links and HTML content without reliance on JS rendering; image alternative text and explicit dimensions.
- Existing About, Makerspace and Competitions URLs retained with relevant current content.

## Intentionally withheld
No AggregateRating, Review, Product Offer, Event, actual CourseInstance, team registration, exact address, business hours or fees in structured data until evidenced. No FAQ rich-result promise. No inflated rankings or conversion claims. robots rules are crawl guidance, not an access-control mechanism; internal source contains no personal lead data.

## After owner verifies launch facts
1. Replace availability statements with real dates, durations, pricing/tax/inclusions and written policies in both languages.
2. Verify address/hours/contact and align the website with a verified Google Business Profile.
3. Submit sitemap and inspect canonical/hreflang coverage in Search Console after publishing.
4. Test deployed pages for Core Web Vitals, mobile usability, indexability and valid structured data.
5. Publish permissioned student projects and teacher information with evidence; do not add invented social proof.
6. If adding analytics, choose a consent/data-handling approach first; current implementation collects only optional source/postal-area information in user-sent inquiries.
